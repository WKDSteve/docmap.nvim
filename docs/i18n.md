# Interface languages

docmap.nvim speaks through a catalog: one JSON file per language, read by a Lua
runtime (editor, engine) and a JavaScript runtime (the generated page). This
page is the contract. A host that embeds the engine or the page
(`docmap-desktop`, the web variant) reads the same contract.

- Catalogs: [`lua/docmap/core/i18n/`](../lua/docmap/core/i18n/), `<locale>.json`
- Shape of a file: [`i18n-catalog.schema.json`](i18n-catalog.schema.json)
- Lua runtime: `lua/docmap/core/i18n/init.lua`
- JavaScript runtime: `lua/docmap/core/render/html/i18n_js.lua`
- Golden cases both runtimes answer alike: `TESTS/fixtures/i18n/cases.json`

## Choosing a language

| Where | Order, first match wins |
|---|---|
| Neovim | `setup({ locale = "de" })`, then `$DOCMAP_LOCALE`, then `v:lang`, then `$LANG` |
| Engine and `scripts/gen_map.lua` | `--locale=de`, then `$DOCMAP_LOCALE`; English otherwise |
| Generated page | `lang=de` in the link's hash, then `?lang=de`, then the choice stored in this browser, then the browser's languages; English otherwise |

A value is a language tag: `de`, `de-AT`, `de_DE.UTF-8`. The exact region wins
when it is shipped (`pt-BR`), the base language otherwise (`de-AT` reads `de`).
A tag no catalog answers, `C` and `POSIX` included, means English: a typo in a
config never blanks the interface.

The engine does not guess from `$LANG` or the operating system: it speaks
English until it is told otherwise. Hosts and CI scripts read its report as
text, and a run that turned German because the machine is German would break
them. A host that shows the report to a person passes `--locale`; a script that
parses it passes nothing, or `--locale=en` to be explicit.

`locale` is not read from `.docmap.json`. That file states facts about the
repository; the language belongs to the reader.

**Neovim follows the language of the system.** On a machine whose `v:lang` is
German, the messages, `:checkhealth` and the quickfix texts are German without
any setting. `setup({ locale = "en" })` keeps English.

## What is translated

The interface: messages, `:checkhealth`, the report of a run, the labels and
explanations of the page, the sentences of the findings.

Never the subject: module names, paths, identifiers, docstring prose, commit
subjects and author names stay as the repository wrote them, in every locale.
In code the two are different calls. A key goes through `t()`; user text is
handed in as a parameter, substituted as it is and never looked up.

Two rules follow for anyone who formats catalog text:

- No case change on it, in Lua (`:upper()`, `:lower()`) or in CSS
  (`text-transform`). Turkish `i` is the standing example. A label that should
  be upper case is written upper case in the catalog.
- Locale names in a picker are endonyms (`Deutsch`), never translated.

## Artifacts stay English

`module_map.json` carries no interface text at all: a finding is a check name
and its parameters. The files a run writes beside it (`overview.md`, SARIF, the
answers of the MCP server) are rendered in English whatever the locale, because
`--check` compares them byte for byte and its verdict must not depend on the
`LANG` of the machine. In code: a renderer of a committed file passes the
source locale explicitly (`findings.format(f, "en")`), an interactive surface
passes nothing and gets the active one.

The generated page is one artifact for every language. It carries all shipped
catalogs and switches in the browser; see [The generated page](#the-generated-page).

## The catalog file

```json
{
  "$schema": "../../../../docs/i18n-catalog.schema.json",
  "locale": "de",
  "name": "Deutsch",
  "tier": "maintained",
  "messages": {
    "finding.missing-readme": "{path} hat keine README.md",
    "page.count.modules": { "one": "{count} Modul", "other": "{count} Module" }
  }
}
```

- `locale` is the file's own name. `name` is the endonym.
- `messages` is flat: one message per line, keys sorted, each key once.
- `en.json` is the source (`"tier": "source"`). Every text is written there
  first; every other file translates it and holds no key it lacks.

### Keys

Dotted segments of letters, digits, `_` and `-`. The first segment names the
surface that owns the text:

| Namespace | Surface |
|---|---|
| `finding.` | The sentence of a finding: `finding.<check>` or `finding.<check>.<variant>` |
| `check.` | What a check compares and why it exists |
| `report.` | Lines of a run's report that every surface shares, and the configuration warnings (`report.config.*`) the editor and the engine both print |
| `cli.` | The engine and `scripts/gen_map.lua` |
| `editor.` | Messages of the commands in Neovim |
| `health.` | `:checkhealth` |
| `page.` | The generated page |

A key names what the text is for, not what it says (`page.tab.hierarchy`, not
`page.hierarchy-label`), so the English can be reworded without renaming.

A host with a catalog of its own keeps its keys out of these namespaces.

### Placeholders

Named, in braces: `{from} requires {to}`. A translation may reorder and repeat
them and may not invent one. A placeholder the caller gave no value for is left
standing (`{to}`), so a template and its caller drifting apart shows on screen.
Values are substituted literally.

Numbers arrive as the caller formatted them. Lua has no ICU and writes
ungrouped ASCII digits everywhere; the page may format with `Intl`. The same
goes for layout: a column padded to a width (`("%-8s"):format(name)`), a
percentage (`("%.0f"):format(share)`) and the indent or line break around a
line are the caller's, so the catalog text is the sentence and nothing else.

A sentence with an optional clause is one key per variant
(`editor.plugins.summary`, `editor.plugins.summary-duplicates`), never a
sentence and a fragment glued to it. The caller picks the key.

A text of several lines is one message with `\n` in it. The advice under a
`:checkhealth` line is written that way (`health.git.missing.advice`): one
paragraph, one list entry per line, and a translation breaks it where it
reads best.

### Plurals

A message that depends on a number is a table of CLDR categories, chosen by
the parameter `count`:

```json
"page.count.files": { "one": "{count} file", "other": "{count} files" }
```

`other` is mandatory and is what a missing category falls back to. Both
runtimes know one rule today: `one` for the number 1 in English, German, Dutch,
Swedish, Italian and Spanish, `other` for everything else. A language with
`few` and `many` gets its rule together with its catalog.

### Tiers

| Tier | Meaning |
|---|---|
| `source` | `en`. |
| `maintained` | Someone who reads the language reviews every change. Complete: the gate fails on an untranslated key. |
| `contributed` | Arrived with a maintainer. Same bar as `maintained`. |
| `machine` | Generated, unreviewed. May be incomplete; shipped only behind an opt-in and marked in the interface. |

## Missing texts are visible

| Case | Renders as |
|---|---|
| The active locale has the key | its text |
| Only English has it | the English text |
| The same, in debug mode | `‹en› ` and the English text |
| No catalog has it | `‹missing:the.key›` |

Never blank and never the bare key. Debug mode is for measuring a half-finished
translation.

A finding of a check that has no catalog entry keeps the form it always had:
`<check-name>` and its parameters.

A catalog file that does not parse is no catalog: its locale reads English as a
whole, and nothing raises.

## The two runtimes

| | Lua | JavaScript |
|---|---|---|
| A text | `require("docmap.core.i18n").t(key, params, locale?)` | `rt.t(key, params, locale)` |
| Which shipped locale a tag means | `normalize(tag)` | `rt.normalize(tag)` |
| First usable of several tags | `resolve(...)` | `rt.resolve([...])` |
| Set the active locale, debug mode | `configure({ locale, debug })` | `rt.configure({ locale, debug })` |
| Plural category | `plural_category(locale, n)` | `rt.pluralCategory(locale, n)` |

`rt` is `docmapI18n(data)`, where `data` is what `core.i18n.for_page()`
returns: `{ source, locales, catalogs }`.

The semantics are the golden file. `TESTS/i18n_runtime_spec.lua` runs every
case through both runtimes; a change of behaviour starts as a change of
`cases.json`.

### Hosts without the files

Not every host of the engine carries files. The packaged binary and the engine
docmap-desktop runs in a browser bundle Lua modules and nothing else. For them
the catalogs exist a second time, as a Lua module:
`lua/docmap/core/i18n/bundled.lua`, the JSON text of every catalog, generated
by `scripts/gen_i18n_bundle.lua`. The runtime reads the files where it can and
the module where it cannot.

A bundler that takes `docmap.core` as a whole has it without being told. One
that lists modules by hand adds `docmap.core.i18n.bundled`.

A host that loads no catalog at all still generates, and that is the trap: a
finding then reads `<missing-readme> path=lua/sample`, and every other text
`‹missing:key›`. The `standalone` gate reads the artifacts of a build for both
shapes.

## The generated page

`index.html` embeds every shipped catalog (the namespaces `page.`, `finding.`
and `report.`) in `<script type="application/json" id="i18n">`, next to the
runtime. Nothing is fetched and no second file is written: one page, every
language, switched without a reload.

**Embedded is not offered.** The page is being moved into the catalog layer by
layer, and a locale is *offered* only once the whole page speaks it: offered
locales appear in the picker (top bar, hidden while there is one) and are
chosen from the browser's languages. Every other shipped locale is reached by
name only, `lang=de` in the hash or `?lang=de`. Today English is offered and
German is embedded. The list is `PAGE_OFFERED` in `core/render/html.lua`.

For a host that embeds the page:

- `?lang=<tag>` sets the language the way `?theme=` sets the theme. A choice
  the reader makes in the page (the hash) wins over it.
- `?i18n=debug` marks every text that fell back to English with `‹en› `.
- The page sets `<html lang>` to the active locale.

**What speaks through the catalog today**: everything the renderer writes
itself (top bar, header counts, tab bar, toolbar, the controls of the
Hierarchy, Compare and Analysis tabs, the findings table), the sub-tabs, the
filter's placeholders, the mark and hidden pills, the copy-link button, and
the sentences of the findings wherever the page shows them. What a panel's
script draws is still English and follows panel by panel.

The static markup says which text it holds, so the script can say it again in
another language:

| Attribute | Meaning |
|---|---|
| `data-i18n="key"` | The element's text is that message. |
| `data-i18n-title`, `-placeholder`, `-aria-label` | That attribute is that message. |
| `data-i18n-params='{"count":3}'` | The parameters of both. |
| `data-i18n-tail="key"` | The text behind a count in a `<b>` (the header counts). |
| `data-finding="3"` | The cell shows finding 3 of `#findings-data`. |

The renderer writes the English text beside each key, so the page reads without
script and the committed artifact stays byte-stable. `TESTS/i18n_page_spec.lua`
fails when a static text has no key or differs from the English of its key.

`#findings-data` carries each finding three ways: `message` (the English
sentence), and `key` with `params` when the catalog has the sentence. A finding
of `opts.extra_checks` brings its own prose and no key, and reads the same in
every locale.

The stylesheet changes the case of no text. The small labels of the page
(section titles, table heads, badges) were upper-cased by `text-transform`
until 2026-11-15; they now show in the case the catalog writes them. The one
exception is the severity of a finding (`error`, `warn`, `info`), the subject
as the report spells it. `TESTS/i18n_page_spec.lua` fails on any other
`text-transform`.

## Adding a text

1. Add the key to `en.json`, in its sorted place, with named placeholders. Write
   whole sentences: a sentence glued from fragments cannot be reordered.
2. Translate it in every `maintained` and `contributed` catalog in the same
   change; the gate fails otherwise.
3. Call `t("the.key", { ... })`.
4. Run `nvim -l scripts/gen_i18n_bundle.lua`: it rewrites `bundled.lua`, the
   copy of the catalogs for hosts without the files. The gate fails on a stale
   copy.

## Adding a language

1. Copy `en.json` to `<locale>.json`, set `locale`, `name` and `tier`.
2. Add the code to `LOCALES` in `lua/docmap/core/i18n/init.lua`.
3. Translate. `scripts/test.sh --file i18n_catalog` prints how many keys are
   translated and names what the format forbids.
4. Run `nvim -l scripts/gen_i18n_bundle.lua`.

## What the gates check

`TESTS/i18n_catalog_spec.lua`: files and `LOCALES` agree; `locale`, `name`,
`tier`; keys sorted, written once, in a known namespace; plural tables have
`other`; a translation has no key and no placeholder its source lacks and the
same shape; `maintained` and `contributed` catalogs are complete; `bundled.lua`
is the files byte for byte, and a host without the files says every sentence
from it.

`TESTS/i18n_runtime_spec.lua`: the golden cases, in Lua and in `node`.

`TESTS/i18n_messages_spec.lua`: the sources of the editor messages, of
`:checkhealth` and of the engine's report, read as text. A key a source names
is in `en.json`; a key under `editor.`, `health.`, `cli.` or `report.` is named
by a source; a call that prints (a `notify` instance, `vim.health`,
`io.stdout`, `io.stderr`) holds no English literal outside `t(...)`. It does
not see a sentence that is built into a variable first, and it runs
`:checkhealth` once to catch a missing key or an unfilled placeholder there.

`TESTS/findings_spec.lua`: every check has its sentence.

`TESTS/i18n_locale_spec.lua`: which surface speaks the active locale and which
names English; where each host takes its locale from.

`TESTS/i18n_page_spec.lua`: no static text or tooltip of the page without a
key; each is the English of its key; every key the page names exists and every
`page.*` key is used; the embedded catalogs and the offered locales; no
`text-transform` in the stylesheet but the severity's.

`TESTS/sheets/interface-language.sheet.lua`: the page in a real window, English
and German, light and dark, the picker and the link.

## Decisions

Taken by the author on 2026-11-15, after the first release of the catalog.

| Question | Decision |
|---|---|
| Does Neovim pick the language by itself? | Yes: `opts.locale`, then `$DOCMAP_LOCALE`, then `v:lang`. `locale = "en"` turns it off. |
| Does the engine follow `$LANG`? | No. English until `--locale=` or `$DOCMAP_LOCALE` says otherwise, because hosts and scripts read its report as text. |
| Is German offered in the page? | Not yet. It is embedded and reached by `lang=de`; it joins the picker and the browser's choice when every panel speaks through the catalog. |
| German wording | The terms of `de.json` as shipped stand, among them "Befunde", "Verlauf", "Modulkarte", "Abgeblendet", "committet", and "Features", "Quicks" and "Treemap" left as they are. The doubtful cases are listed in the task of the German locale and are settled when the page is looked at in a window. |
